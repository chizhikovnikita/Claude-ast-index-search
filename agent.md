# Работа с форком ast-index

Этот форк сохраняет чтение Windows-1251 и других старых кодировок при
обновлении исходного ast-index. Рабочий репозиторий —
`https://github.com/chizhikovnikita/Claude-ast-index-search`.
`https://github.com/defendend/Claude-ast-index-search` — источник обновлений,
доступный только для чтения. Коммиты создавай локально в ветках форка;
отправлять коммиты, ветки и теги разрешено только в репозиторий форка.
Этот запрет распространяется на прямые URL и другие имена remote.

## Где искать код

- `src/main.rs`: clap CLI и вызовы команд; `src/commands/`: поиск, навигация,
  управление индексом, граф символов и сигналы Git.
- `src/indexer.rs`: обход файлов, определение стека и обновление индекса;
  `src/encoding.rs`: единое декодирование содержимого исходников.
- `src/parsers/`: tree-sitter, запросы и резервные парсеры.
- `src/db.rs`: SQLite, миграции, блокировки и публикация поколений индекса.
- `crates/ast-index-mcp/`: отдельный stdio JSON-RPC сервер, запускающий CLI.
- `tests/`: интеграционные проверки; тесты функций также находятся в модулях.

Для структуры используй `ast-index explore`, `symbol`, `refs` и `outline`.
Для текста, строковых литералов и регулярных выражений используй `rg`.
После изменения файлов выполни `ast-index update`; после обновления версии
или схемы выполни `ast-index rebuild`. Старый индекс и заметки о состоянии
сверяй с текущими исходниками.

## Инварианты форка

- Читай содержимое исходников через `encoding::read_file_to_string` или
  `encoding::decode_bytes`, сохраняя UTF-8 fast path и legacy fallback.
  Не перекодируй пользовательские файлы на диске. Конфиги с гарантированным
  UTF-8 могут читаться напрямую.
- Проверяй кириллицу Windows-1251 в полном rebuild, incremental update,
  поиске, выводе фрагментов и командах, читающих исходники без индекса.
  Смешанный проект с UTF-8 и Windows-1251 должен работать целиком.
- Храни пути относительно корня-владельца; разрешай их через `PathResolver`.
  Не подменяй native-пути строковым разбором по одному виду разделителя.
- Отделяй stdout с результатами/JSON от stderr с диагностикой. JSON не
  должен содержать ANSI-коды или посторонние сообщения.
- Сохраняй рабочий индекс при ошибке rebuild/update; не обходи блокировки
  и атомарную публикацию базы ради успешного завершения команды.

## Рабочий цикл

Перед правками прочитай `CLAUDE.md` и применимые `.claude/rules/`, проверь
`git status` и diff. Сохраняй пользовательские изменения и локальные
`.agents/skills`/`.sds`; не добавляй их в коммиты форка.
Правила обновления и запрет upstream push находятся в
`.claude/rules/fork-workflow.md`. Не запускай `scripts/bump.sh` при обычной
синхронизации: он создаёт коммит, тег и выполняет push.

Windows-помощник `scripts/dev.ps1` задаёт окружение только на время команды:

```powershell
./scripts/dev.ps1 Build
./scripts/dev.ps1 Test
./scripts/dev.ps1 Install
./scripts/dev.ps1 Index
./scripts/install-push-guard.ps1
```

`Build` собирает release workspace; `Test` запускает весь release workspace
с продолжением после ошибок и отдельным временным кэшем. Для тестов LTO
выключена и используются 16 codegen units; обычная сборка и установка
используют release-профиль проекта. `Install` устанавливает текущий checkout,
`Index` перестраивает индекс текущего проекта собранным или установленным CLI.
Для Windows GNU можно задать `AST_INDEX_MINGW_BIN` или `-CompilerBin`;
для каталога сборки — `CARGO_TARGET_DIR` или `-TargetDirectory`.
Абсолютные пути конкретного пользователя не добавляй в tracked-конфиги.

## Проверка результата

После функциональных изменений собери release workspace и запусти полный
набор тестов на Windows и Ubuntu. Дополнительно проверь реальный сценарий:
rebuild → поиск известного символа → изменение файла → update → поиск.
Для изменений MCP проверь stdio JSON-RPC. Тесты должны использовать
временный кэш, а не индекс рабочего проекта.

Сообщай точные результаты, оставшиеся ошибки и различия с исходным baseline;
не скрывай тесты и не объявляй старые сбои автоматически допустимыми.
Если доступна `.sds/state.md`, обновляй её проверенными фактами после работы,
не публикуя локальные пути, логи и заметки в репозиторий.
